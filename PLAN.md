# План и решения: система без логинов и паролей

Документ фиксирует, **как** устроена текущая версия Visits11 и **почему** приняты
именно такие решения. Краткое описание для пользователя — в `README.md`,
разбор безопасности — в `SECURITY.md`, сборка — в `BUILD.md`.

> 📌 **Памятка для ИИ (следующий этап — USB-коробочка-считыватель на `ESP32 Devkit V1 + PN532 V3`):**
> Полный список заказанных комплектующих, схема соединения 4 проводами без пайки и техническое задание на прошивку `ESP32 + PN532` и доработку `KubGAU-Journal.exe` находятся в файле **[`ESP32_READER_PLAN.md`](ESP32_READER_PLAN.md)**.

## 1. Что просили изменить

1. Убрать логины и пароли полностью — из программы на ПК («даже колонку логина
   и пароля в exe преподавателя»), из приложений студентов, из экспорта.
2. Напротив каждого студента — кнопка «показать QR-код».
3. Экспорт студентов — только QR-коды.
4. В приложениях студента — ровно два способа входа: камера на QR-код или картинка
   из галереи; больше ничего («и всё, больше ничего»).
5. Всё работает **без интернета и без сети** (Wi-Fi). Единственный канал между
   телефонами — NFC-касание: Android ↔ iPhone.
6. Ничего другого в системе не ломать: четыре приложения остаются, NFC-касание
   остаётся обязательным, интерфейс без переделок.

## 2. Итог: как теперь работает вход

```
    ПК: «Студенты» → «Экспорт QR-кодов» → папка «QR-коды <группа>»
        <ФИО>.png на каждого студента + «Как войти.txt»
                          │
        (файл отдают студенту — или показывают код на экране ПК)
                          ▼
    Студент: «Сканировать QR-код» (камера)  ИЛИ  «Загрузить из галереи»
                          │
        код сохраняется в настройках телефона — это и есть вход
                          ▼
    Отметка: телефон студента прикладывается к телефону преподавателя (NFC)
```

Логин и пароль не нужны: их роль выполняет код студента (128 бит случайности),
который лежит в его личном QR-коде. Вход выполняется один раз и навсегда; сменить
студента — долгое нажатие по статусу («выйти»).

## 3. Решения, которые стоит запомнить

| Решение | Почему так |
|---|---|
| Вход — только QR (камера или галерея), ручного ввода нет | Прямое требование. Логин/пароль убираются целиком, а не прячутся «на всякий случай» |
| QR-код **постоянный**, не сгорающий | Один файл на семестр: не нужно перевыпускать и объяснять студентам. Сгораемый код потребовал бы связи с ПК в момент входа — а сети нет |
| Вместо пароля — 128 бит случайности из `RandomNumberGenerator` | Перебрать код невозможно (в отличие от 10-символьного пароля, который теперь не нужен) |
| Формат `V11S2` вместо `V11S1` | В `V11S1` лежали логин и пароль. Из-за смены состава полей старые PNG не читаются — это ожидаемо, коды всё равно сменились вместе со схемой базы |
| Wi-Fi-фолбэк для телефонов без NFC удалён | Требование «без сети». Телефон студента без NFC отметиться не может — преподаватель ставит отметку вручную |
| У приложения студента **нет** разрешения `INTERNET` | Чтобы «без сети» было подтверждаемым фактом, а не обещанием: см. `SECURITY.md` §4 |
| Телефон преподавателя слушает только адрес USB-интерфейса | Отрезает Wi-Fi полностью: из сети телефон недоступен, брандмауэр Windows не нужен |
| ПК сам ищет телефон (исходящими запросами) | Брандмауэр Windows не мешает входящим — но исходящие соединения он пропускает всегда |
| Ищем телефон **только** среди USB-адаптеров (`RNDIS/USB/tether`) | Чтобы ПК не сканировал Wi-Fi и не мог «найти» чужой сервер в сети |
| Метка «Телефон» в таблице студентов вместо колонки «ID телефона» | Из `app` ушёл `PhoneId` (он был частью старой схемы). В таблице теперь честный статус: привязан телефон к студенту или нет |
| Экспорт студентов в Word удалён, экспорт занятия оставлен | «Экспорт — только QR-коды»: таблица с логином и паролем потеряла смысл, журнал занятия к этой теме не относится |
| QR рисует сам ПК (QRCoder), без обращений к интернету | Библиотека локальная, картинки генерируются офлайн |
| При экспорте ПК разбирает свой же QR и сверяет CRC | Картинки не могут разойтись с тем, что читают приложения: ошибка формата обнаружится сразу, а не на телефоне студента |
| Камера на iPhone — `AVFoundation`, распознавание — `Vision` | Системные средства, без сторонних библиотек и без интернета |
| Камера на Android — своя, внутри того же окна (системная камера + `zxing:core` на кадре NV21) | Сторонний экран-сканер (`zxing-android-embedded`) вылетал на новых Android и тянул лишние библиотеки; свой экран — часть приложения, ломаться нечему, а распознавание то же самое |
| Приложению преподавателя нужно разрешение `INTERNET` | Без него Android не даёт создать вообще ни один сокет (EACCES) и не отдаёт список сетевых интерфейсов: сервер связи с ПК не открывался, а на экране висело «включите USB-модем». Разрешение нужно только как допуск к сокетам — слушаем по-прежнему единственный адрес USB-интерфейса |

## 4. Формат QR-кода (один на всех платформах)

```
V11S2.<код b64url>.<ФИО b64url>.<crc32>
Student: Ivanov Ivan Ivanovich
Code: QVJISVBPVl9JSQ
```

- читается только первая строка; две нижние — для человека;
- base64url без выравнивания: кириллица в ФИО не ломает QR (текст остаётся ASCII);
- `crc32` — 8 hex-символов (IEEE 802.3, одинаковый на C#, Java и Swift):
  отсекает чужие картинки и кривые распознавания. Это контроль целостности, не подпись.

Реализации: `Services/StudentQr.cs` (ПК), `android/student/.../MainActivity.java`
(`parsePayload`), `ios/Sources/QrLogin.swift` (`StudentQrCredentials.parse`).

## 5. Протокол касания (короткая справка)

1. Студент читает HCE-карту телефона преподавателя: AID `F0391101020304`.
2. Команда: `INS 0x10`, данные `код-студента\nDeviceId`.
3. Телефон преподавателя кладёт запрос в очередь; ПК забирает его по `GET /event`
   (long-poll 3 с) и отвечает `POST /event_result` (`{"id":N,"code":C,"value":"..."}`).
4. Студент получает `[код][имя UTF-8]`: `0` — отмечен, `2` — кода нет в журнале,
   `4` — не получилось (перекличка не идёт / ПК недоступен), `5` — телефон привязан
   к другому студенту.

## 7. Проверка

- CI собирает все четыре файла: `build.yml` (exe), `apk.yml` (два APK), `ios.yml` (ipa).
- Локальные проверки формата: CRC32/base64url сверены с эталонными реализациями
  (Python `zlib.crc32`, `base64.urlsafe_b64encode`) на одних и тех же строках.
- Ручной сценарий на живых телефонах: экспорт QR → вход камерой → вход картинкой →
  отметка касанием → повторная отметка → «чужой телефон» → удаление студента.

## 8. Что осталось за рамками (осознанно)

- **Метка «Что-то не так» не сохраняется в БД** — живёт только во время занятия
  (риск `R-3` в `SECURITY.md`).
- **Шифрование канала ПК ↔ телефон** (общий секрет/HMAC) — не сделано (`R-1`).
- **Keychain / EncryptedSharedPreferences** для кода студента — не сделано (`R-2`).
- **Аппаратная аттестация устройства** — не делалась (`R-4`).

## 9. Подводные камни (на будущее)

- **iOS:** QR в формате `V11S1` из старой версии не читается — формат сменился вместе
  с базой. Приложения трёх платформ нужно обновлять одновременно.
- **Android:** экран сканирования — свой; не подключать обратно сторонние
  библиотеки-сканеры (`zxing-android-embedded` и подобные): их экран вылетал
  на новых Android. Нужен только `zxing:core` — он без ресурсов и экранов.
- **Android:** без разрешения `INTERNET` приложение не может создать ни одного
  сокета (даже свой, для USB). Поэтому оно есть у приложения преподавателя
  и не нужно (и не объявлено) приложению студента.
- **Android:** у приложения студента нет `INTERNET` — если добавлять сетевой код,
  сборка не «сломается», но на устройстве запросы молча упадут. Это защита от возврата
  Wi-Fi-пути.
- **ПК:** поиск телефона идёт только по USB-адаптерам; если у студента/телефона
  адаптер называется иначе, телефон не найдётся — добавьте пометку в `UsbAdapterMarks`.
- **ПК:** перенос старой базы: `PRAGMA foreign_keys=OFF` на время перестройки таблицы
  `Students` — иначе `DROP TABLE` утащит за собой `Attendance`.
- **SDK:** Android-модули зафиксированы на SDK 34, Gradle 8.9, JDK 17 — не поднимать
  без необходимости, сборка в CI проверена именно на них.
