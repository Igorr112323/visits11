# План работ: вход студента по QR-коду (без сервера)

Документ отвечает на четыре вопроса из постановки задачи: план по файлам,
ключевые фрагменты кода, зависимости и разрешения, подводные камни. Он же
фиксирует решения, принятые по ходу разбора репозитория.

---

## 1. Что выяснилось при разборе (и что из этого следует)

| В постановке | Как на самом деле в репозитории |
|---|---|
| «удалить `server.exe`» | `server.exe` нет. «Сервер» — это HTTP-эндпоинты внутри ПК-программы «Журнал КубГАУ»: `Services/PhoneServer.cs` (порты 8090–8099: `/api/login`, `/api/qr`, `/api/nfc_mark`, `/api/ping`) |
| «всё перенести на телефоны» | Телефон преподавателя (`android/app/`) сам является сервером (`ServerSocket :8090`) + NFC-картой (`TeacherCardService.java`), но своей базы и интерфейса у него нет: каждое касание он пересылает на ПК и ждёт ответ ≤ 4 с |
| «Android → iPhone по NDEF + BLE» | Уже работает прямой NFC: `ios/Sources/ContentView.swift` через `NFCTagReaderSession(.iso14443)` читает HCE преподавателя (AID `F0391101020304`, APDU INS `0x10`). Bluetooth не нужен вообще |
| «вход студента по QR из галереи» | Этого не было: телефон преподавателя QR-коды студентов не показывал (их сканировала камера преподавателя), студент iOS умел только вводить логин/пароль вручную |

**Принятые решения (по ответам заказчика):**

1. Архитектура остаётся: ПК-журнал + телефон преподавателя по кабелю + APK студента + APK преподавателя + iOS-приложение. Ничего не удаляем.
2. Новое — **вход студента по статичному QR-коду**: ПК экспортирует папку с картинками, студент выбирает свою картинку из галереи.
3. **NDEF + BLE не делаем**: прямой NFC уже работает, а BLE-путь добавляет разрешения, диалог сопряжения, +2–5 с на касание и риски iOS в фоне (Bluetooth Classic с iOS вообще невозможен).
4. NFC-касание остаётся единственным способом отметиться «вплотную» — ничего не упрощаем.

**Почему «без сервера» в буквальном смысле не получилось без переезда:** отметка
студента — это запись в базу, которая живёт на ПК. Пока истина (группы, студенты,
логины, занятия) хранится в `attendance.db` рядом с exe, любой вход и любая отметка
так или иначе упираются в ПК. Чтобы совсем убрать ПК, нужно переносить базу, вход,
журнал и всю логику отметок в приложение преподавателя — это отдельная большая
работа с новыми экранами (см. раздел 9).

## 2. Схема нового потока

```
ПК «Журнал КубГАУ»                           Студент (Android / iPhone)
────────────────────────                     ─────────────────────────────
Вкладка «Студенты»
  «Экспорт QR-кодов»
   └─ папка «QR-коды ИСП-31»
        ├─ Иванов Иван Иванович (IVANOV_II).png
        ├─ Петров Пётр Петрович (PETROV_PP).png
        └─ Как войти.txt                     картинка уходит студенту
                                             (мессенджер/почта/флешка)
                                                   │
                                                   ▼
                                             сохраняет в галерею
                                                   │
                                             «Войти по QR из галереи»
                                                   │  ZXing (Android) / Vision (iOS)
                                                   ▼
                                             логин + пароль в телефоне
                                                   │
                                             дальше как раньше: NFC-касание
                                             (Wi-Fi-фолбэк — на Android без NFC)
```

## 3. Формат QR-кода студента

Собирается на ПК в `Services/StudentQr.cs`, разбирается в
`android/student/.../MainActivity.java` и `ios/Sources/QrLogin.swift`.

```
V11S1.<логин-b64url>.<пароль-b64url>.<ФИО-b64url>.<crc32>
Login: ARHIPOV_II
Password: K7M2QX9P
```

- **1-я строка — машинная**, 2-я и 3-я — для человека (можно отсканировать любым
  QR-сканером и ввести данные руками — это и есть «фильтр от потери доступа»).
- **`V11S1`** — версия формата. Меняется только вместе с форматом: старые APK её не поймут.
- **base64url без выравнивания** — благодаря этому QR остаётся ASCII-текстом:
  кириллица в ФИО (UTF-8) упаковывается, а не ломает кодировку QR. Никаких
  «выбери ECI/UTF-8» на ПК, никаких догадок декодера на телефоне.
- **CRC32** (IEEE 802.3, 8 hex-символов) от машинной строки без последнего поля.
  Одинаково считается на ПК, Android (`java.util.zip.CRC32`) и iOS (свои 10 строк).
  Отсекает чужие картинки, обрезанные/пересжатые снимки и кривые распознавания.
- Формат **не** связан с перекличкой: QR живёт, пока преподаватель не перевыпустит
  файлы (пароли при этом не меняются). QR переклички (AES, ~10 секунд) остаётся
  там, где был, — в Wi-Fi-фолбэке.

## 5. Ключевые фрагменты

### 5.1. Android: картинка из галереи → логин

```java
// системный пикер: разрешения не нужны, файл отдаёт сама система
if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.TIRAMISU) {
    intent = new Intent(MediaStore.ACTION_PICK_IMAGES);      // «выбор фото» (13+)
} else {
    intent = new Intent(Intent.ACTION_OPEN_DOCUMENT);        // «Документы»/галерея
    intent.addCategory(Intent.CATEGORY_OPENABLE);
}
intent.setType("image/*");
startActivityForResult(intent, REQ_PICK_QR);

// распознавание (фоновый поток): обычный QR и «негатив» — скриншоты тёмной темы
RGBLuminanceSource source = new RGBLuminanceSource(width, height, pixels);
String text = tryDecode(source, hints);
if (text == null) {
    text = tryDecode(source.invert(), hints);
}
```

### 5.2. iPhone: картинка из галереи → логин

```swift
// распознавание средствами системы — без разрешений и без сторонних библиотек
let request = VNDetectBarcodesRequest()
request.symbologies = [.qr]
try VNImageRequestHandler(cgImage: cgImage, options: [:]).perform([request])
let text = (request.results ?? []).compactMap { $0.payloadStringValue }.first

// выбор фото — системный, вне процесса приложения
provider.loadObject(ofClass: UIImage.self) { object, _ in ... }
```

### 5.3. Android HCE преподавателя (как было — не менялось)

```java
// TeacherCardService: студент прикладывает телефон, ПК отвечает на касание
int instruction = apdu[1] & 0xFF;
if (instruction == 0xA4) return ok(new byte[0]);        // выбор приложения
if (instruction == 0x10) { ... requests.add(json); ... } // данные студента → ПК
```

Протокол: AID `F0391101020304`, команда INS `0x10`, `[type][данные]`,
ответ — код (`0` вход, `1` отмечен, `2` неверный пароль, `3` перелогин,
`4` ПК недоступен, `5` телефон привязан к другому аккаунту) + значение.

### 5.4. ПК: рисование QR

```csharp
var data = new QRCodeGenerator().CreateQrCode(text, QRCodeGenerator.ECCLevel.M);
return new PngByteQRCode(data).GetGraphic(12);   // module 12 px — читается с фото экрана
```

## 7. Подводные камни

### iOS (самое важное)

1. **HCE на iPhone невозможна.** iPhone не может «притворяться картой»: телефон
   студента — только считыватель. Поэтому отметка на iPhone — это всегда
   «iPhone → телефон преподавателя», а не наоборот.
2. **NDEF + BLE — не делаем.** iOS не поддерживает NFC-OOB-сопряжение: пришлось бы
   руками соединяться по BLE (разрешение Bluetooth, foreground-сервис рекламы на
   Android, диалог сопряжения, +2–5 с на касание, риск выгрузки приложения в фон),
   а Bluetooth Classic (SPP) с iOS недоступен вообще. Прямой NFC-путь уже работает
   и заметно быстрее.
3. **PHPicker вместо камеры/галереи «с разрешением».** `PHPickerViewController`
   работает вне процесса приложения, поэтому доступ к галерее не запрашивается и
   ключ в `Info.plist` не нужен. Если однажды захочется встроенный сканер камерой —
   это `NSCameraUsageDescription` + AVCaptureSession и **новый экран**, то есть
   изменение интерфейса.
4. **Vision, а не `CIDetector`.** `CIDetector(ofType: CIDetectorTypeQRCode)` даёт
   сырые CIQRCodeDescriptor и хуже читает мелкие/повёрнутые коды;
   `VNDetectBarcodesRequest` — современный путь и работает с iOS 11+.
5. **Формат — только ASCII.** Если бы в QR попала кириллица, часть сканеров
   показала бы «кракозябры», а QRCoder мог бы уйти в UTF-8/ECI. Base64url снимает
   вопрос полностью.
6. **Минимальная версия iOS 15** (как в `ios/project.yml`) — `VNDetectBarcodesRequest`,
   `PHPickerViewController` и SwiftUI `.bordered` доступны; ничего поднимать не нужно.
7. **Телефон студента должен быть подписан** (Sideloadly, подпись живёт 7 дней) —
   это особенность бесплатной установки, к QR-входу отношения не имеет.

### Android

8. **Никаких разрешений на хранилище.** `ACTION_PICK_IMAGES` (13+) и
   `ACTION_OPEN_DOCUMENT` отдают `content://`-ссылку и право чтения — читаем через
   `ContentResolver`. `READ_MEDIA_IMAGES`/`READ_EXTERNAL_STORAGE` не нужны
   (и запрошены не будут — иначе отклонение политики Google Play).
9. **Большие фото.** Снимок 12 МП в `Bitmap` — это ~48 МБ и OOM на слабом телефоне:
   перед декодированием читаем размеры и подбираем `inSampleSize` (длинная сторона
   ~720–1400 px), распознаём в фоновом потоке, `Bitmap.recycle()` после.
10. **Инвертированный QR.** Скриншот из мессенджера с тёмной темой — белый код на
    чёрном фоне: ZXing такое не читает, поэтому есть вторая попытка с `source.invert()`.
11. **Пересжатие картинки мессенджером** убивает часть модулей QR. Лечится запасом:
    ECC level M, module 12 px, а в файле-инструкции студенту написано сохранять
    картинку целиком.

### ПК и данные

12. **Статичный QR = логин + пароль.** Кто получил файл — тот может войти под этим
    студентом (в отличие от QR переклички, живущего 10 секунд). Поэтому:
    файлы раздаются адресно, в инструкции написано не пересылать их другим.
    Отметку «за другого» это всё равно не открывает: аккаунт привязан к первому
    телефону (`DeviceId`), и с чужого устройства отметка отклоняется.
13. **Имена файлов и БД.** Имя картинки = «ФИО (логин)», запрещённые в Windows
    символы заменяются, тёзки получают суффикс «(2)». При повторном экспорте старые
    `*.png` в этой же папке удаляются — включая картинки удалённых студентов.
14. **Переустановка приложения не лечится QR-кодом.** Привязка аккаунта к телефону
    хранится в базе ПК (`Students.DeviceId`), а ID устройства после переустановки
    новый — вход по QR даст ответ `5` («аккаунт привязан к другому телефону»), как и
    ручной ввод. Это защита, а не ошибка: привязку снимают удалением и повторным
    созданием студента (история отметок при этом теряется) — либо правкой
    `DeviceId` в базе напрямую.
15. **Пароли не меняются при экспорте.** Файлы можно выгружать сколько угодно раз;
    чтобы пароль «перестал работать», студента нужно удалить/пересоздать — это
    отдельное пожелание, в текущем объёме не делалось.

## 8. Как проверить

1. **ПК:** вкладка «Студенты» → выбрать группу → «Экспорт QR-кодов» → выбрать папку.
   Ожидаем: папка «QR-коды <группа>», картинки по числу студентов, «Как войти.txt»,
   тост «QR-коды готовы».
2. **Любой QR-сканер:** в коде видны «Login: …» и «Password: …» — проверка руками,
   что формат читается не только нашим приложением.
3. **Android:** перенести картинку в телефон → «КубГАУ Студент» → на экране входа
   «Войти по QR из галереи» → выбрать картинку → тост «Вход выполнен: <ФИО>» →
   касание NFC ставит отметку.
4. **iPhone:** сохранить картинку в «Фото» → приложение → «Войти по QR из галереи» →
   выбрать → экран отметки → касание NFC.
5. **Отрицательные проверки:** выбрать чужую картинку (ожидаем «В этой картинке нет
   кода для входа»), QR переклички, обычную фотографию, скриншот с тёмной темы.
6. **Сборка:** `build.yml` (exe), `apk.yml` (оба APK), `ios.yml` (ipa) на GitHub Actions —
   все три workflow запускаются на push и собирают артефакты в релиз `v1.0.0`.

## 9. Что осталось за рамками (осознанно)

- **Встроенный сканер камерой** в приложении студента: нужен `CAMERA` + новый экран
  (нарушает «интерфейс не менять»). Пока роль сканера выполняет любое приложение
  с QR-сканером — по строкам `Login:`/`Password:` в самом коде.
- **Полный отказ от ПК** (база, вход, журнал на телефоне преподавателя): отдельная
  большая работа — перенос `attendance.db` в SQLite на телефоне, экраны групп и
  журнала, выгрузка на ПК. Требует решения о новых экранах.
- **NDEF + BLE** — см. пункт 2 раздела «Подводные камни»: прямой NFC уже покрывает
  сценарий iOS.
- **Смена пароля по QR** (одноразовые/сгорающие коды) — можно добавить позже,
  формат к этому готов: достаточно поднять версию до `V11S2` и дописать поля.
