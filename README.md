# КубГАУ · Учёт посещаемости

Система состоит из двух Windows-программ, Android-приложений преподавателя и студента и студенческого приложения для iPhone.

| Приложение | Назначение |
|---|---|
| `KubGAU-Server.exe` | Постоянный сервер, принимает и хранит ожидающие отметки iPhone |
| `KubGAU-Journal.exe` | Журнал преподавателя: база, группы, занятия, отметки и экспорт |
| `KubGAU-Teacher.apk` | Android преподавателя: NFC для Android-студентов и BLE-касание с iPhone |
| `KubGAU-Student.apk` | Android-студент: вход по QR-коду и прямое NFC-касание |
| `Visits11-Student-iOS-unsigned.ipa` | iPhone-студент: вход по QR-коду, BLE-касание и отложенная отправка отметок |

## Как проходит отметка

```text
Android-студент ── NFC ──> Android-преподаватель ── USB/локальная связь ──> Журнал

iPhone-студент ── BLE-касание ──> подтверждение на iPhone
       │
       └── интернет появится позже ──> Серверный EXE ──> Журнал преподавателя
```

- Для первого входа нажмите «Сканировать QR-код» в студенческом приложении и разрешите доступ к камере. QR содержит уникальный ID студента, ФИО и адрес сервера. Сканирование не требует интернета; после него данные сохраняются на телефоне.
- QR-код постоянный и может сканироваться повторно. Он не одноразовый.
- При каждой отметке преподавательский журнал сравнивает ID текущего телефона с зарегистрированным ID. Несовпадение не блокирует отметку: преподаватель видит красную строку и красную пометку в журнале.
- Вкладка «Студенты» преподавательского EXE содержит кнопки показа QR-кода и сброса ID телефона.
- iPhone хранит неподтверждённые сервером отметки локально и повторяет отправку, пока сервер не ответит успешно.
- Сервер хранит полученные отметки в SQLite до подтверждения преподавательским журналом. Повторная отправка одной отметки не создаёт дубликат.
- Для Android ↔ Android остаётся прямой NFC-путь. Он использует локальный релей преподавательского EXE на порту 8090.

## Первый тест на одном компьютере

Нужен Windows 10/11 x64. Сервер и журнал запускаются как два отдельных EXE на одном Windows-ПК. Сервер слушает порт `8091`; преподавательский EXE забирает отметки с сервера.

1. Запустите `KubGAU-Server.exe`. В окне появятся адреса и ключ преподавательского журнала.
2. Если отметки будут отправляться с настоящего телефона, подключите ПК и телефон к одной Wi-Fi-сети. Разрешите входящие подключения для серверного EXE в брандмауэре Windows.
3. Запустите `KubGAU-Journal.exe`, нажмите кнопку статуса сервера в верхней панели и укажите адрес сервера и скопированный ключ. Для самого журнала на этом же ПК подходит `http://127.0.0.1:8091`; для телефона в QR-код автоматически попадёт LAN-адрес ПК.
4. Создайте группу и студентов во вкладке «Студенты». У нужного студента нажмите «QR» и отсканируйте код приложением студента.
5. На Android преподавателя разрешите Bluetooth/NFC, держите приложение открытым во время касаний. На iPhone включите Bluetooth и оставьте студенческое приложение открытым для BLE-касания.
6. Начните занятие в журнале. Отметки Android проходят через NFC; отметки iPhone отправляются на сервер сразу или после восстановления интернета.

`localhost`/`127.0.0.1` на телефоне указывает на сам телефон, а не на ПК. Телефон использует LAN-адрес, который показывает серверный EXE.

## Перенос на постоянный сервер

Сначала проверьте схему на локальной сети. Для размещения в интернете:

1. Установите серверный EXE на Windows-сервер с постоянным IP или доменным именем.
2. Настройте HTTPS reverse proxy (например, Caddy или nginx) перед локальным HTTP-портом `8091`. Не публикуйте открытый HTTP-порт в интернет.
3. Откройте серверу входящий доступ через reverse proxy, настройте резервное копирование файла `server.db`.
4. В преподавательском EXE укажите HTTPS-адрес и ключ, который показывает серверный EXE.
5. Показывайте студентам QR-коды уже после настройки окончательного адреса. QR включает адрес сервера; если адрес меняется, QR нужно отсканировать заново.

Сервер сохраняет базу и ключ в `%LOCALAPPDATA%\KubGAU\Visits11\Server`. Преподавательский журнал хранит свою базу `attendance.db` рядом с EXE.

## Устройство и красное предупреждение

При первой отметке с QR-привязанного телефона журнал сохраняет ID устройства. Следующая отметка с другим ID всё равно фиксируется, но строка студента и соответствующая запись занятия показываются красным с предупреждением «ID телефона не совпадает с зарегистрированным». Во вкладке «Студенты» преподаватель может сбросить сохранённый ID; тогда ближайшая отметка зарегистрирует текущее устройство.

ID установки приложения не является IMEI. Android использует `ANDROID_ID`, iPhone — сохранённый UUID приложения.

## Установка iPhone-приложения

IPA в релизе собирается без подписи. Для установки на личный iPhone его нужно подписать Apple ID через Sideloadly; бесплатная подпись обычно действует ограниченное время. Для массового распространения потребуется Apple Developer Account и подписание приложения.

## Сборка и проверки

Windows EXE собираются на Windows с .NET 8 SDK:

```powershell
dotnet build Visits11.csproj -c Release
dotnet build Server/Server.csproj -c Release
dotnet publish Visits11.csproj -c Release -r win-x64 -p:PublishSingleFile=true -p:SelfContained=true -p:IncludeNativeLibrariesForSelfExtract=true -o publish-journal
dotnet publish Server/Server.csproj -c Release -r win-x64 -p:PublishSingleFile=true -p:SelfContained=true -p:IncludeNativeLibrariesForSelfExtract=true -o publish-server
```

Android APK собираются с JDK 17, Android SDK 34 и Gradle 8.9:

```powershell
cd android
gradle testReleaseUnitTest lintRelease assembleRelease --no-daemon
```

iPhone-приложение собирается на macOS с Xcode и XcodeGen. GitHub Actions выполняет сборки Windows, Android и iOS, а Windows job дополнительно проверяет HTTP API сервера: сохранение отметок, повторную отправку, ключ преподавателя, очередь и подтверждение получения.
