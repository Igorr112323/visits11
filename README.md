# КубГАУ · Учёт посещаемости (Visits11)

Полностью офлайн-система учёта посещаемости: преподаватель отмечает студентов
касанием телефон-к-телефону (NFC), журнал ведётся на ПК. Интернет не нужен
вообще — только USB-кабель между ПК и телефоном преподавателя.

| Файл | Что это | Где видно название |
|---|---|---|
| `KubGAU-Journal.exe` | Программа на ПК (Журнал КубГАУ) | окно «Журнал КубГАУ» |
| `KubGAU-Teacher.apk` | Телефон преподавателя | приложение «КубГАУ Преподаватель» |
| `KubGAU-Student.apk` | Телефон студента (Android) | приложение «КубГАУ Студент» |
| `web/student/` | Телефон студента (iPhone) | веб-приложение «КубГАУ», ставится на экран «Домой» |

Все файлы — в [релизах](https://github.com/Igorr112323/visits11/releases)
(страница **КубГАУ · Учёт посещаемости**). Имена файлов — латиницей:
GitHub не допускает кириллицу в именах файлов, все названия внутри — русские.

**iPhone — без App Store, без Apple ID и без подписи.** Приложение для iPhone
это не отдельный файл, а страница, которую раздаёт сам ПК: студент открывает её
в Safari и добавляет на экран «Домой» — см. [iPhone](#iphone-pwa-вместо-приложения).

## Быстрый старт

**ПК (преподаватель):**
1. Скачайте `KubGAU-Journal.exe` в любую папку и запустите (Windows 10/11 x64,
   установка не требуется).
2. Вкладка «Студенты» → создайте группу → добавьте студентов (или импортируйте
   из Word). Каждому выдаются логин и пароль.
3. Вкладка «Занятия» → выберите группу → **«Начать перекличку»**.
   Пока перекличка идёт — студенты отмечаются.

**Телефон преподавателя:**
1. Установите `KubGAU-Teacher.apk`.
2. Подключите телефон к ПК USB-кабелем.
3. Приложение само попросит включить «USB-модем» и откроет нужный экран
   настроек (единственный тумблер, который Android не разрешает включать
   приложениям). Включите его.
4. Дождитесь зелёной надписи **«ПК подключён, NFC готов»** — телефон-терминал
   готов, больше ничего вводить не нужно. Положите телефон на стол.

**Телефон студента (Android):**
1. Установите `KubGAU-Student.apk`.
2. Первый запуск: введите выданные логин и пароль — один раз и навсегда.
3. Чтобы отметиться: откройте приложение и приложите телефон **задней стороной**
   к телефону преподавателя. Успех — двойная вибрация и «Вы отмечены».

**Телефон студента (iPhone):** ничего устанавливать из интернета не нужно —
ПК сам раздаёт приложение. Адрес показан на вкладке **«Занятия»** в блоке
«Телефон студента (iPhone)» — нажмите на него, чтобы скопировать. Откройте этот
адрес в Safari, войдите логином и паролем, затем «Поделиться» → «На экран
„Домой“». Подробно — в разделе [iPhone](#iphone-pwa-вместо-приложения).

## Как это работает

```
                    USB-кабель («USB-модем»)
   ┌──────────┐  ←──────────────────────────→  ┌──────────────────┐
   │   ПК     │   все соединения исходящие    │ Телефон           │
   │ Журнал   │   со стороны ПК — брандмауэр  │ преподавателя     │
   │ КубГАУ   │   Windows ничего не блокирует │ (NFC-терминал)    │
   └──────────┘                               └──────────────────┘
      ↑  GET /event (забрать касания)              ↑  NFC-касание
      │  POST /event_result (вернуть ответ)        │  (телефон-к-телефону)
      │  Wi-Fi: /api/login, /api/nfc_mark, /api/qr  │
   ┌──────────────────────────────────────────────────────────────┐
   │  Телефоны студентов: Android (NFC) и iPhone (PWA)            │
   └──────────────────────────────────────────────────────────────┘
```

- **NFC «телефон к телефону».** Телефон преподавателя «притворяется картой»
  (Android Host Card Emulation), телефон студента работает считывателем.
  Отметиться может только тот, кто физически приложил телефон, — переслать
  скриншот или отметить «за соседа» невозможно.
- **Pull-модель (без брандмауэра).** ПК сам забирает касания с телефона
  преподавателя (`GET /event`, long-poll) и возвращает ответ
  (`POST /event_result`). Все соединения — исходящие со стороны ПК, поэтому
  **настраивать брандмауэр Windows не нужно вообще**: включён он или выключен —
  без разницы.
- **Wi-Fi-путь (iPhone и телефоны без NFC).** Студент открывает приложение,
  оно общается с ПК по локальной сети (`POST /api/login`, `POST /api/nfc_mark`,
  `GET /api/ping`), а ПК дополнительно отдаёт запасной QR-код (`GET /api/qr`) —
  его можно показать камере преподавателя. QR шифруется AES ключом текущей
  переклички, содержит нонс и живёт ~10 секунд — скриншот бесполезен. Этот путь
  чувствителен к настройкам брандмауэра (входящие подключения), поэтому
  на Android основной способ — NFC.

## Возможности

### Программа на ПК («Журнал КубГАУ»)
- **Занятия** — выбор группы, «Начать перекличку», живой список с «Есть»/«Нет»,
  круговая статистика; клик по строке — ручная отметка/снятие.
- **Студенты** — группы и студенты: создание, **удаление** (✕ у студента,
  «Удалить группу» — с подтверждением), логины/пароли (клик по чипу — копирование),
  импорт из Word (.docx), экспорт в Word.
- **Журнал** — история занятий, детали посещаемости, экспорт занятия в Word.
- **Подсказки преподавателю**: каждое неудачное касание видно на ПК —
  «логин не найден», «неверный пароль», «перекличка не идёт».
- **Адрес для iPhone** — на вкладке «Занятия»: клик по адресу копирует его
  в буфер обмена (та же страница отдаёт приложение студента-айфонщика).
- Светлая и тёмная темы (сохраняются в `settings.json` рядом с exe).

### Защита от накруток
- **Привязка аккаунта к устройству.** При первом входе аккаунт студента
  привязывается к уникальному ID его телефона (Android — `ANDROID_ID`,
  iPhone в браузере — 16 hex-символов, которые веб-приложение генерирует один
  раз и хранит в `localStorage`). Вход или отметка с чужого телефона отклоняются.
  Если студент очистит данные сайта в Safari, ID создастся заново — тогда
  аккаунт потребуется привязать к новому «устройству» у преподавателя.
- **«Что-то не так».** Если телефон, уже привязанный к одному студенту, попытались
  использовать для входа/отметки за другого (например, студент удалил приложение
  и заново вошёл, чтобы «помочь кенту») — попытка блокируется, а строка
  настоящего владельца телефона подсвечивается в журнале меткой
  «⚠ Что-то не так» с подсказкой.
- **Вечный вход.** Токены сессий хранятся в базе — перезапуск ПК (и даже
  переустановка приложения студента) не разлогинивает. Если токен всё же
  неизвестен ПК — касание само восстанавливает вход по привязанному телефону.
- **Перепутать ответы нельзя.** Каждый ответ касания снабжён номером запроса:
  ответ одного студента физически не может достаться другому.
- **Вибрация.** При успешной отметке телефон Android делает заметный двойной пульс.

### Телефон студента на iPhone (PWA)
- Отдельное приложение для iPhone — это веб-страница, которую раздаёт сам ПК:
  ни App Store, ни Apple ID, ни подписи, ни IPA-файлов.
- **Вход по логину и паролю** и **кнопка «Отметиться»** — как в Android-версии,
  тексты сообщений и коды ответов ПК те же.
- **Автологин:** токен хранится в браузере, при следующем запуске сразу экран отметки.
- **Кнопка связи с ПК** в углу: зелёная «ПК онлайн» / красная «Нет связи с ПК»
  (опрос `GET /api/ping` каждые 5 секунд). Без связи кнопка отметки заблокирована.
- **Внутренние баннеры** сверху экрана (успех — зелёный, ошибка — красный,
  подсказка — фиолетовый): «Вы отмечены, {имя}», «НЕВЕРНЫЙ ЛОГИН ИЛИ ПАРОЛЬ»,
  «Перекличка не идёт», «Нет связи с ПК», «Этот телефон привязан к другому
  аккаунту», «Сессия истекла».
- **Вибрация на iPhone ограничена Apple** — вместо неё пульсирует зелёная галочка
  (см. [iPhone](#iphone-pwa-вместо-приложения)).
- **В запасном режиме** на экране отметки виден QR-код: покажите его камере
  преподавателя, если кнопка почему-то не сработала.

## Решение проблем

| Симптом | Причина и решение |
|---|---|
| Телефон препода: «Нет связи с ПК» | Не включён «USB-модем» (нажмите на надпись — откроются настройки) или не запущен exe. |
| Телефон препода: «NFC ВЫКЛЮЧЕН» | Нажмите на надпись → включите NFC в настройках. |
| Студент: «НЕВЕРНЫЙ ЛОГИН ИЛИ ПАРОЛЬ» | Проверьте логин/пароль на вкладке «Студенты» на ПК, введите заново и приложите телефон ещё раз. |
| Студент: «Не получилось, попробуйте ещё раз» | На ПК всплывает подсказка: чаще всего перекличка не запущена или студент не из выбранной группы. |
| Студента «выкинуло» на экран входа | Так выглядит неверный логин/пароль (см. выше) — просто введите правильные. |
| На ПК пропали студенты и группы | exe запущен из другой папки: база `attendance.db` лежит рядом с exe. Запустите из прежней папки (или перенесите файл базы). |
| Вибрации нет | Проверьте, что вибрация включена в настройках телефона (на части Xiaomi/Huawei слабая по умолчанию). На iPhone вибрация веб-приложениям недоступна — вместо неё пульсирует зелёная галочка. |
| iPhone: «Нет связи с ПК» | Телефон и ПК должны быть в одной сети Wi-Fi, exe — запущен. Адрес должен совпадать с адресом ПК: `http://<IP ПК>:8090`. Если IP ПК изменился, откройте приложение по новому адресу и заново добавьте на экран «Домой». |
| iPhone: нет пункта «На экран „Домой“» | Страница открыта не в Safari (например, в Chrome или во встроенном браузере из другого приложения) — откройте адрес именно в Safari. |
| iPhone: приложение открывается с адресной строкой | Оно открыто во вкладке Safari, а не с иконки. Добавьте на экран «Домой»: «Поделиться» → «На экран „Домой“». |
| iPhone: подсказки появляются баннером сверху, а не как уведомления iOS | Так и задумано: системные уведомления iOS требуют HTTPS, а приложение работает по локальному адресу. |
| «Брандмауэр Windows блокирует» | Этого сообщения больше не бывает: ПК сам забирает отметки, настраивать брандмауэр не нужно. Для Wi-Fi-пути (iPhone) и входящих подключений может понадобиться разрешить приложению доступ в частной сети. |

## Протокол обмена (для разработчиков)

### NFC (телефон студента → телефон преподавателя)
Выбор приложения: `00 A4 04 00 07 F0391101020304` → `9000`.
Команда (INS `0x10`): `[type][data] + 9000`, где data в UTF-8:
- type 1 (первый вход): `login\npassword\deviceId`
- type 2 (далее): `token\ndeviceId`

Коды ответа (первый байт):
`0` — вход выполнен, дальше токен (и отметка уже стоит) · `1` — отмечен, дальше
имя · `2` — неверный логин/пароль · `3` — сессия неизвестна (перелогин) ·
`4` — не получилось (перекличка не идёт / ПК недоступен) · `5` — аккаунт
привязан к другому телефону.

Телефон преподавателя кладёт запрос в очередь; ПК забирает его по
`GET /event?wait=3000` (200 + JSON или 204), обрабатывает и возвращает ответ
в `POST /event_result` (`{"code":N,"value":"...","id":M}` — id защищает от
перепутанных ответов). Обмен касаниями сериализован, ожидание ответа ≤ 4 с
(укладывается в 5-секундный таймаут IsoDep).

### Сервер ПК (порты 8090–8099, Wi-Fi-фолбэк студентов)
- `POST /api/login` `{login,password,device}` → `{ok,name,token}` /
  `{ok:false,device:true}` (чужой телефон) / `{ok:false}`
- `GET /api/qr?token=` → PNG текущего QR (204 — перекличка не идёт, 401 — токен)
- `POST /api/nfc_mark` `{token,device}` → `{ok,name}` / `{ok:false,relogin}` /
  `{ok:false,device:true}`
- `GET /api/ping` → `{"app":"visits11-server"}`
- Статика PWA студента отдаётся тем же сервером (файлы из папки `web/student`,
  а если её рядом с exe нет — из встроенных в сборку копий):
  `GET /` → `index.html`, `GET /setup` → `setup.html`,
  `GET /app.js` → `application/javascript`, `GET /style.css` → `text/css`,
  `GET /manifest.json` → `application/manifest+json`,
  `GET /fonts/*` → `font/woff2`, `GET /icons/*` → `image/png` или `image/x-icon`.

### База данных (SQLite, `attendance.db` рядом с exe)
Таблицы: `Groups`, `Students` (логин/пароль, `DeviceId` — привязка телефона),
`Lessons`, `Attendance`, `Sessions` (токены — вход «навсегда»).

## Сборка из исходников

**ПК (Windows, [.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0)):**
```bash
dotnet publish -c Release -r win-x64 -p:PublishSingleFile=true -p:SelfContained=true -p:IncludeNativeLibrariesForSelfExtract=true
```

**Android (JDK 17, Gradle 8.9, SDK 34):**
```bash
cd android && gradle assembleRelease
# app/build/outputs/apk/release/app-release.apk       — преподаватель
# student/build/outputs/apk/release/student-release.apk — студент
```

**iPhone (PWA студента):** собирать нечего — это статика в `web/student/`
(HTML/CSS/JS без библиотек и без сборщика). ПК раздаёт её своим встроенным
сервером; шрифты уже сконвертированы в `.woff2`, иконки — в `icons/`.
Если меняли `.ttf` в `Assets/Fonts`, пересоберите `.woff2` (например,
`fonttools`): `python -m fontTools.ttLib.woff2 compress Manrope-Regular.ttf`.

### Автосборка (GitHub Actions)
- `build.yml` → `KubGAU-Journal.exe` (Windows-раннер, single-file, релиз)
- `apk.yml` → `KubGAU-Teacher.apk`, `KubGAU-Student.apk` (релиз)

Раннер возвращает в релиз только актуальные имена файлов (старые удаляет).

## iPhone: PWA вместо приложения

Отдельного приложения для iPhone больше нет: вместо него — то же самое
приложение, но веб-версия (**PWA**), которую раздаёт сам ПК. Ни App Store,
ни Apple ID, ни подписи, ни IPA-файлов, ни интернета.

**Установка (3 шага):**
1. **Открыть Safari** на iPhone и ввести адрес ПК — он написан в программе
   на вкладке «Занятия», в блоке «Телефон студента (iPhone)»: нажмите на адрес,
   чтобы скопировать его и отправить студенту. Открывается страница-мастер
   `http://<IP ПК>:8090/setup` с QR-кодом и картинками.
2. **Войти** логином и паролем, которые выдал преподаватель, — и нажать
   «Поделиться» (квадрат со стрелкой ↑) → **«На экран „Домой“»** → «Добавить».
3. **Готово:** иконка «КубГАУ» на экране «Домой» открывает приложение на весь
   экран, без адресной строки. Отметка — кнопкой «Отметиться» во время переклички.

**Как это устроено.** Приложение — это HTML/CSS/JS, которое отдаёт встроенный
сервер ПК (`web/student/`). Никаких внешних запросов: ни CDN, ни шрифтов Google,
ни аналитики. Service Worker не используется (и не нужен — приложение тонкое и
работает в реальном времени), HTTPS тоже не нужен: Safari спокойно открывает
`http://` в локальной сети.

**Ограничения iPhone (честно, это ограничения Apple, а не приложения):**
- **Вибрация.** `navigator.vibrate()` в Safari не реализован, Web Audio не даёт
  тактильной отдачи (звук на 0.001 Гц и громкости 0.0001 просто не воспроизводится).
  Поэтому вибрация на iPhone **не сработает** — вместо неё при успешной отметке
  пульсирует зелёная галочка (CSS `@keyframes pulse`, масштаб 1 → 1.15 → 1,
  0.4 секунды, 2 повтора). На Android Chrome вибрация работает.
- **Системные уведомления (Notification API).** iOS показывает их только
  приложениям с экрана «Домой» **и только по HTTPS**. Наш ПК отдаёт `http://`,
  поэтому системные уведомления, скорее всего, недоступны. Приложение пытается
  (если браузер разрешает — показывает), но основной способ — **всплывающие
  баннеры прямо в приложении**: они работают всегда, без разрешений и без HTTPS.
- **Привязка к телефону.** В браузере нет `ANDROID_ID`, поэтому устройство
  опознаётся по случайному ID (16 hex-символов) в `localStorage` Safari. Если
  очистить данные сайта, ID изменится — вход придётся повторить, а ПК увидит
  новый телефон (преподавателю нужно отвязать старое устройство).
