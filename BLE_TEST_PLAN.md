# Приёмочные проверки BLE 2.0

Автоматически: Windows WPF publish, Android teacher/student release, iOS unsigned build, скетч ESP32 core 2.0.17; структурные проверки общего протокола и исключения NFC.

На аппаратуре (не запускались в sandbox):
- Android 8–11: location permission+service; Android 12+: nearby devices; отказ и повторная выдача разрешения.
- iPhone: разрешить/запретить Bluetooth, выключить/включить, свернуть/вернуться.
- Закрыть приложение, перезагрузить телефон: сохранённый студент остаётся.
- 10 циклов: долгий тап → камера → вход → долгий тап → фото → вход. Отмена, неверный QR, огромное фото, поворот/уход в фон во время камеры/декодирования.
- 2/4/5/0: неизвестный студент выходит; нет переклички/USB и блокировка устройства НЕ выходят; успех — отметка в БД и вибрация. Повторить с обоими терминалами.
- Долгий тап во время ожидания BLE-ответа → войти другим QR. Поздний ответ старого запроса не должен удалить нового студента.
- Извлечь USB во время запроса, вернуть. Таймаут не удаляет вход; автоматическое восстановление связи.
- ESP32: COM занят, установлен не тот скетч, подключено несколько USB UART. Неизвестная подпись не получает студентов/настройки.
- Все 4 мощности из EXE, переподключение, перезапуск EXE. На плате ответы P содержат выбранный уровень. Проверить дальность с разными корпусами; RSSI не точный дальномер.
- Два телефона одновременно: ответы не перепутаны, повторная отметка не создаёт дубль. Поздний R с чужим id игнорируется платой.
- Минимальное окно EXE 1160×720: вкладки и Bluetooth не накладываются, смена темы и выбор уровня работают без перетаскивания окна.
- До/после обновления сравнить список групп, студентов, QR и посещений; не использовать пустую базу.

Ограничения: протокол QR+BLE без аутентификации терминала; сброс при коде 2 относится к журналу, ответившему на запрос. Нельзя отличить удалённого студента от QR другой базы без нового идентификатора журнала в QR. APK debug-подпись старого CI не сохранена; вход при удалении приложения сохранить невозможно.
