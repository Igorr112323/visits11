# Тестовый сценарий: проверяем всё от сервера до отметки

Порядок — от простого к сложному. Этап 1 можно пройти вообще без телефонов.

---

## Этап 0. Автотесты сервера (2 минуты)

```bash
cd server
python -m venv .venv && source .venv/bin/activate    # Windows: .venv\Scripts\activate
pip install -r requirements.txt
pytest -v
```

**Ожидаемо:** `16 passed`. Тесты проверяют: создание пары, приём отметки,
подтверждение касанием, дубль, чужой `device_id`, несовпадение предмета/
преподавателя, истёкшую и закрытую пару, синхронизацию телефона преподавателя,
идемпотентность, CSV и журнал отказов.

## Этап 1. Сервер руками через curl (5 минут)

```bash
# 1. запустить сервер (в отдельном окне)
uvicorn main:app --host 0.0.0.0 --port 8000

# 2. создать пару
SID=$(python3 -c "import uuid;print(uuid.uuid4())")
TS=$(date --iso-8601=seconds)          # macOS: date -u +"%Y-%m-%dT%H:%M:%SZ"
curl -s -X POST http://127.0.0.1:8000/api/session \
  -H 'Content-Type: application/json' \
  -d "{\"session_id\":\"$SID\",\"subject\":\"Информатика\",\"teacher_id\":\"IVANOV_II\",\"group_name\":\"ИС-21\",\"minutes\":90}"

# 3. «касание» телефона преподавателя
curl -s -X POST http://127.0.0.1:8000/api/tap \
  -H 'Content-Type: application/json' \
  -d "{\"session_id\":\"$SID\",\"tap_time\":\"$TS\"}"

# 4. отметка студента
curl -s -X POST http://127.0.0.1:8000/api/attendance \
  -H 'Content-Type: application/json' \
  -d "{\"session_id\":\"$SID\",\"student_id\":\"s001\",\"device_id\":\"IOS-TEST-0001\",
       \"timestamp\":\"$TS\",\"subject\":\"Информатика\",\"teacher_id\":\"IVANOV_II\",
       \"student_name\":\"Иванов Иван\"}"
```

**Проверки:**

| Шаг | Ожидаемый ответ |
|---|---|
| 2 | `{"ok":true,"session":{…,"status":"active"}}` |
| 3 | `{"ok":true,"added":true,"marks_verified":0}` |
| 4 | `result":"accepted"`, `"verified":true` |
| повтор шага 4 | `"result":"duplicate"` (второй записи в базе нет) |
| шаг 4 c другим `student_id` и тем же `device_id` | код 409, `reason":"device_mismatch"` |
| шаг 4 с `subject` = «Физкультура» | код 409, `reason":"subject_mismatch"` |
| шаг 4 с `session_id` = случайный UUID | код 404, `reason":"unknown_session"` |

Итог: `curl -s http://127.0.0.1:8000/api/attendance/$SID | python3 -m json.tool`

```json
{
  "present_count": 1,
  "present": [{"student_id": "s001", "student_name": "Иванов Иван", "verified": 1, "source": "ios"}],
  "absent": [],
  "rejected": [{"reason": "device_mismatch"}]
}
```

Ещё: `…/export.csv` (открывается в Excel) и `http://<IP>:8000/docs` (Swagger).

## Этап 2. Android-терминал (10 минут)

Подготовка: телефон с NFC (Android 8+), установленный APK, тот же Wi-Fi, что и ноутбук.

1. Запустите сервер, посмотрите IP (например `192.168.1.10`).
2. Откройте приложение на Android, введите адрес сервера, «Сохранить адрес»,
   «Проверить связь» → точка **зелёная**, надпись «Сервер отвечает».
3. Заполните «Информатика», «ИС-21», `IVANOV_II`, 90 минут → **«Создать пару»**.
4. **Ожидаемо:** появилась карточка «Текущая пара», идёт таймер, сгенерирован UUID,
   кнопка «Начать эмуляцию метки» (по умолчанию эмуляция уже включена — зелёная точка).
5. Проверьте на сервере: `curl -s http://127.0.0.1:8000/api/sessions | python3 -m json.tool`
   — пара должна быть в списке (телефон её отправил).
6. Нажмите «Показать QR-код для iPhone» → отобразится QR; он обновляется каждые 5 секунд.
7. Убедитесь, что HCE работает: скачайте на другой Android любое приложение-сканер
   NFC-меток (например «NFC Tools»), приложите к телефону преподавателя — увидите
   NDEF-сообщение с MIME-типом `application/vnd.kubgau.attendance+json` и JSON внутри.

**Если сервер выключить** (Ctrl+C) и создать пару — пара сохранится в Room,
в приложении появится «Сервер недоступен: пара сохранена и уедет при синхронизации».
После запуска сервера нажмите «Синхронизировать» — пара появится в `/api/sessions`.

## Этап 3. iPhone-студент (10–20 минут, включая подпись)

Подготовка: iPhone с iOS 16+, приложение установлено (см. [INSTALL_AND_SIGNING.md](INSTALL_AND_SIGNING.md)),
телефон в той же Wi-Fi-сети.

1. «Настройки» → адрес сервера `192.168.1.10`, логин `s001`, ФИО «Иванов Иван» →
   «Проверить связь» → «есть».
2. Первый запуск: разрешите доступ к **локальной сети**.
3. Вкладка «Отметиться»:

   * **QR-путь (работает с бесплатной подписью):** нажмите «Отметиться по QR-коду»,
     наведите камеру на QR на телефоне преподавателя. Должно появиться
     «Вы отмечены: Информатика».
   * **NFC-путь (нужен платный аккаунт Apple):** нажмите «Отметиться», приложите
     iPhone **верхней частью** к задней стороне Android-телефона. Появится системное
     окно и сообщение «Отметка получена».

4. Проверьте сервер: `curl -s http://127.0.0.1:8000/api/attendance/$SID | python3 -m json.tool`
   — новая запись с `verified: 1`.
5. В приложении на Android счётчик «Отметились» увеличился до 1 (опрос раз в 5 секунд),
   в списке — ФИО студента и время.

### Проверка очереди без сети

1. Выключите сервер (`Ctrl+C`) — или включите на iPhone режим полёта **без Wi-Fi**.
2. Отметьтесь по QR (QR-код всё ещё на экране).
   **Ожидаемо:** «Сервер недоступен. Отметка сохранена и уйдёт автоматически».
   В «Мои отметки» запись со статусом **«в очереди»**.
3. Включите сервер обратно (или Wi-Fi). Через 5–20 секунд статус меняется на
   «подтверждено»/«принято», а на сервере появляется отметка.
   (Повторы идут автоматически: 5 с → 15 с → 45 с → 2 мин.)

## Этап 4. Проверка защиты от обмана (5 минут)

| Что проверяем | Как воспроизвести | Ожидаемо |
|---|---|---|
| Повторная отметка | отметьтесь дважды в одну пару | второе — «уже было», в `/api/attendance` одна строка |
| Чужой телефон | установите приложение на второй iPhone, введите **тот же** логин `s001` | отметка отклонена, `device_mismatch`; в отчёте появляется запись в `rejected` |
| Отметка за соседа | на втором iPhone введите логин `s002`, но телефон уже привязан к `s001` | `device_mismatch` (если наоборот — сначала `s002`, потом `s001`) |
| Подделка метки | создайте пару через `/api/session` с другим предметом и попробуйте отправить отметку с предметом из настоящей метки | 409 `subject_mismatch` |
| Пара закрыта | нажмите «Закрыть пару» в Android | новые отметки — 409 `session_closed`, у студента «Сервер отклонил отметку» |
| Отметка без присутствия | отключите эмуляцию на Android (телефон не отвечает как метка), отправьте отметку через curl без касания | `accepted_unverified`, `verified: 0` — видно «без касания» |
| Скриншот QR | сделайте скриншот QR, подождите 30 секунд, отправьте данные из скриншота через curl | `accepted_unverified` (свежесть не подтверждена касанием) |

## Этап 5. Нагрузка: 20 студентов (по желанию)

1. Проще всего — скриптом (эмулируем то, что делает iPhone):

```bash
for i in $(seq 1 20); do
  TS=$(date --iso-8601=seconds)
  curl -s -X POST http://127.0.0.1:8000/api/tap -H 'Content-Type: application/json' \
    -d "{\"session_id\":\"$SID\",\"tap_time\":\"$TS\"}" > /dev/null
  curl -s -X POST http://127.0.0.1:8000/api/attendance -H 'Content-Type: application/json' \
    -d "{\"session_id\":\"$SID\",\"student_id\":\"s$i\",\"device_id\":\"IOS-$i\",
         \"timestamp\":\"$TS\",\"subject\":\"Информатика\",\"teacher_id\":\"IVANOV_II\"}" \
    | python3 -c "import sys,json;d=json.load(sys.stdin);print('s$i', d.get('result'))"
done
curl -s "http://127.0.0.1:8000/api/attendance/$SID" | python3 -c \
  "import sys,json;d=json.load(sys.stdin);print('присутствует:', d['present_count'])"
```

**Ожидаемо:** 20 отметок, `present_count: 20`; в приложении преподавателя счётчик
«Отметились» = 20, список прокручивается; в базе 20 строк.

2. Реальный стресс-тест: 5–10 телефонов студентов по очереди отмечаются у
   Android-терминала. Касания обрабатываются последовательно (это ограничение
   самого NFC), поэтому на группу из 20 человек уходит примерно 1–2 минуты.
