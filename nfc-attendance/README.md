# КубГАУ · Отметки касанием: Bluetooth-метка + NFC (FastAPI + Kotlin + Swift)

Полностью локальная система отметки посещаемости: **сервер на ноутбуке
преподавателя**, **Android-телефон — метка-терминал**, **iPhone студента
прикладывают к нему, и отметка ставится сама**. Интернет не нужен, публикации
в интернете нет.

| Компонент | Технологии | Папка |
|---|---|---|
| Локальный сервер | Python 3.11+, FastAPI, SQLite | [`server/`](server/) |
| Телефон преподавателя | Kotlin, BLE (advertising + GATT-сервер) и NFC HCE | [`android/`](android/) |
| Телефон студента | Swift + SwiftUI, CoreBluetooth, CoreNFC, Core Data | [`ios/`](ios/) |
| Документация | схема БД, установка, тестовый сценарий | [`docs/`](docs/) |

Документы: [схема БД](docs/DB_SCHEMA.md) · [установка и подпись iOS/Android](docs/INSTALL_AND_SIGNING.md) · [тестовый сценарий](docs/TEST_SCENARIO.md)

## Как это выглядит для студента

1. Открывает приложение и прикладывает iPhone к телефону преподавателя.
2. Через 1–2 секунды — галочка: «Вы отмечены. Иванов И.И., 10:03».
3. Убирает телефон. Никаких кнопок, QR-кодов и сканирований.

Снаружи это ровно как NFC/Apple Pay. Основной канал — **Bluetooth**: он работает
без платного аккаунта Apple и без системных окон. **NFC** остался запасным путём
(отдельная кнопка внизу экрана) — для тех, у кого есть платный аккаунт.

| Канал | Кто умеет | Условие |
|---|---|---|
| **Bluetooth (BLE)** — основной | все iPhone и Android | ничего не нужно: приложение студента само находит метку терминала |
| **NFC (HCE)** — запасной, кнопкой | Android-студенты; iPhone — только с платным аккаунтом Apple | телефон преподавателя «притворяется» NDEF-меткой |

Почему Bluetooth — основной: **NFC-чтение на iPhone требует capability
«NFC Tag Reading», которую Apple выдаёт только за $99/год**
([источник](https://www.freecodecamp.org/news/the-ios-nfc-handbook-how-to-read-write-and-lock-nfc-tags-with-react-native)),
а Bluetooth работает с бесплатной подписью.

## Как это работает

```
       Wi-Fi (роутер или точка доступа ноутбука) — интернет не нужен
  ┌────────────────┐   POST /api/session, /api/sync     ┌──────────────────┐
  │  Ноутбук       │ ←───────────────────────────────── │  Android         │
  │  преподавателя │                                    │  преподавателя   │
  │  FastAPI +     │   POST /api/attendance             │  (BLE + NFC)     │
  │  SQLite        │ ←───────────────────────────────── │                  │
  └────────────────┘                                    └──────────────────┘
           ▲                                                     ▲
           │ GET /api/attendance/{session_id}                    │ касание
           │                                          Bluetooth (BLE) / NFC
  ┌────────────────┐
  │  iPhone         │  нашёл метку → проверил расстояние → отправил отметку
  │  студента       │
  └────────────────┘
```

1. Преподаватель запускает сервер: `uvicorn main:app --host 0.0.0.0 --port 8000`.
2. В Android-приложении создаёт пару (предмет, группа, свой id) и жмёт
   «Начать эмуляцию метки».
3. Телефон преподавателя начинает **вещать BLE-метку**: сервис с токеном,
   который меняется каждые 5 секунд, и мощность излучения подобрана так, чтобы
   «доставать» только до телефона, который реально приложили.
4. Студент прикладывает iPhone. Приложение студента:
   * слышит метку и смотрит на **уровень сигнала (RSSI)**;
   * подключается и читает данные пары;
   * убеждается, что сигнал сильнее порога (телефон действительно рядом);
   * отправляет отметку обратно на терминал и получает подтверждение.
5. Отметка сохраняется локально (Core Data / Room) и уезжает на сервер;
   без сети она ждёт в очереди и уходит автоматически.
6. Терминал отправляет на сервер свои «касания» — с телефоном студента и
   измеренным RSSI. Сервер по ним **подтверждает** отметку.
7. Преподаватель видит живой список: `GET /api/attendance/{session_id}`.

### Что происходит «под капотом» BLE

| Шаг | Что делает терминал | Что делает iPhone |
|---|---|---|
| 1 | `BluetoothLeAdvertiser`: сервис `A110` + Service Data (8-байтовый токен), режим LOW_LATENCY, мощность ULTRA_LOW | `CBCentralManager.scanForPeripherals` по сервису, `AllowDuplicates` |
| 2 | — | В `didDiscover` есть RSSI: слабее −80 dBm — не подключаемся |
| 3 | `BluetoothGattServer` принимает подключение | Подключается, читает характеристику `A111` (данные пары и порог сигнала) |
| 4 | — | `readRSSI()` несколько раз: если сигнал слабее порога, показывает «Поднесите ближе» |
| 5 | Принимает запись в `A112` (по частям, если длинно) | Пишет JSON: `device_id`, имя, токен из рекламы, время, RSSI |
| 6 | Проверяет токен (окно 5–10 с), пишет касание в Room, шлёт ACK в `A113` | Получает ACK → «Вы отмечены» |
| 7 | `POST /api/sync` с касаниями (device_id + rssi) | `POST /api/attendance` с отметкой (source `ble`, rssi) |

## Защита от отметок «из коридора»

Три независимых барьера — именно то, что нужно, чтобы отметиться мог только тот,
кто физически приложил телефон:

1. **Мощность излучения.** По умолчанию режим «Вплотную»: `ADVERTISE_TX_POWER_ULTRA_LOW`
   — сигнал физически не достаёт до коридора (единицы метров через стены).
   Это ограничение физики, а не кода приложения.
2. **Порог RSSI в приложении студента.** Метка принимается только если сигнал
   сильнее порога, который задаёт преподаватель: «Вплотную» −60 dBm (5–10 см),
   «Рядом» −68 dBm (до ~0,5 м), «Свободно» −78 dBm (до ~2 м).
3. **Проверка на сервере.** Отметка считается подтверждённой, только если:
   * есть касание терминала в окне ±20 секунд **и** его `device_id` совпадает
     с телефоном студента;
   * присланный RSSI не ниже жёсткого порога (−80 dBm) — слабые отметки
     помечаются как неподтверждённые и видны преподавателю.

Честная оговорка: порог RSSI проверяет приложение студента (Android-as-GATT-server
не умеет измерять RSSI подключившегося клиента). Поэтому главный барьер —
мощность излучения, а RSSI нужен, чтобы преподаватель видел в журнале, где
реально был телефон: «−48 dBm» — приложен, «−88 dBm» — из коридора.

## Остальная защита

* **`session_id` — случайный UUID** на каждую пару: заранее записанная метка не подойдёт.
* **Токен метки меняется каждые 5 секунд** — запись «на будущее» невозможна.
* **Повторная отметка** в ту же пару блокируется (уникальность `session_id + student_id`).
* **`device_id` генерируется один раз** (на iPhone — в Keychain, переживает
  переустановку): отметка с чужого телефона — `device_mismatch`.
* Все отклонённые попытки пишутся в `rejected_marks`.

## Быстрый старт

### 1. Сервер (ноутбук преподавателя)

```bash
cd server
python -m venv .venv
# Windows:  .venv\Scripts\activate
# macOS/Linux:  source .venv/bin/activate
pip install -r requirements.txt
uvicorn main:app --host 0.0.0.0 --port 8000
```

В консоли появится адрес вида `http://192.168.1.10:8000` — его вводят телефоны.
Тесты: `pytest -v` (22 проверки, включая BLE-касания и отсев слабого сигнала).

### 2. Android-приложение преподавателя

* Готовый APK (1,7 МБ, подписан):
  **[скачать](https://github.com/Igorr112323/visits11/releases/download/nfc-v1.0.0/NFC-Attendance-Teacher.apk)** —
  ставится файлом или `adb install -r`.
* Локально: открыть `android/` в Android Studio (JDK 17).

В приложении: адрес сервера → «Проверить связь» → предмет/группа/свой id →
«Создать пару» → выбрать дистанцию («Вплотную» по умолчанию) → «Начать эмуляцию
метки». Телефон начнёт вещать; разрешите Bluetooth и уведомления — метка работает
в фоне, чтобы не гаснуть, пока телефон лежит на столе.

### 3. iOS-приложение студента

* Готовый неподписанный `.ipa` (231 КБ):
  **[скачать](https://github.com/Igorr112323/visits11/releases/download/nfc-v1.0.0/NFC-Attendance-Student-unsigned.ipa)**;
  подписать своим Apple ID (даже бесплатным) на компьютере: нужны
  [Sideloadly](https://sideloadly.io/SideloadlySetup64.exe) и, на Windows,
  [iTunes](https://www.apple.com/itunes/download/win64) +
  [iCloud](https://updates.cdn-apple.com/2020/windows/001-39935-20200911-1A70AA56-F448-11EA-8CC0-99D41950005E/iCloudSetup.exe)
  с сайта Apple. Пошагово:
  [инструкция](docs/INSTALL_AND_SIGNING.md#31-установка-и-подпись-через-sideloadly--пошагово-windows-или-macos).
* Или `xcodegen generate` в `ios/` и ▶ в Xcode.

В приложении: «Настройки» → адрес сервера и логин → вкладка «Отметиться» →
приложить iPhone к телефону преподавателя. Ничего нажимать не нужно.

## API сервера

| Метод | Путь | Кто вызывает | Назначение |
|---|---|---|---|
| `GET` | `/api/health` | оба | проверка связи |
| `POST` | `/api/session` | преподаватель | создать пару (UUID) |
| `GET` | `/api/sessions` | преподаватель | список пар |
| `GET` | `/api/session/{id}` | оба | данные пары |
| `POST` | `/api/session/{id}/close` | преподаватель | закрыть пару |
| `POST` | `/api/attendance` | студент | отметка (`source`: `ble`/`nfc`, поле `rssi`) |
| `GET` | `/api/attendance/{id}` | оба | присутствующие + отклонённые попытки |
| `GET` | `/api/attendance/{id}/export.csv` | преподаватель | выгрузка в Excel |
| `POST` | `/api/tap` | преподаватель | касание терминала (`device_id`, `rssi`) |
| `POST` | `/api/sync` | преподаватель | пары + касания одним запросом |
| `GET` | `/api/taps/{id}` | преподаватель | журнал касаний |

Ответы на отметку:

| Код | `result` | Значение |
|---|---|---|
| 200 | `accepted` | принята и подтверждена касанием нужного телефона |
| 200 | `accepted_unverified` | принята, подтверждения нет (нет касания или слабый сигнал) |
| 200 | `duplicate` | уже отмечался в эту пару |
| 404 | `unknown_session` | пары нет на сервере |
| 409 | `session_closed` / `session_expired` | пара закрыта или истекла |
| 409 | `subject_mismatch` / `teacher_mismatch` | данные метки не совпали с парой |
| 409 | `device_mismatch` | телефон привязан к другому студенту |

Swagger: `http://<IP>:8000/docs`.

## Протокол метки

| Что | Значение |
|---|---|
| BLE-сервис | `0000A110-0000-1000-8000-00805F9B34FB` |
| Service Data | 8-байтовый токен = HMAC-SHA256(секрет пары, окно 5 с) |
| `A111` (read) | `{session_id, subject, teacher_id, group, min_rssi, range, token_ttl}` |
| `A112` (write) | `{device, name, token, time, rssi}`, части: первый байт 0x01 «дальше», 0x00 «конец» |
| `A113` (notify) | `{code, message}`: 0 — принято, 2 — устаревший токен, 3 — перекличка не идёт, 4 — слишком часто |
| NFC (HCE) | NDEF Type 4 Tag, AID `D2760000850101`, MIME `application/vnd.kubgau.attendance+json` |
| Дистанции | «Вплотную» ULTRA_LOW/−60 dBm · «Рядом» LOW/−68 · «Свободно» MEDIUM/−78 |

## Ограничения

* Нужна общая сеть: телефон и ноутбук в одном Wi-Fi (или через мобильную точку
  доступа ноутбука). Bluetooth-касание работает без сети, но отметки уезжают на
  сервер, когда связь есть.
* iPhone **читает** метки, но не эмулирует: HCE на iOS нет — поэтому метку всегда
  создаёт Android-телефон преподавателя.
* Bluetooth проходит через стены: если выставить «Свободно», отметка из коридора
  становится возможной. По умолчанию стоит «Вплотную».
* NFC-путь на iPhone требует платный аккаунт Apple ($99/год); Bluetooth — нет.
* Бесплатная подпись iOS живёт 7 дней — потом подписать заново (данные сохраняются).
