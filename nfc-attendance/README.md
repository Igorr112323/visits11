# КубГАУ · NFC-отметки посещаемости (FastAPI + Kotlin + Swift)

Полностью локальная система отметки посещаемости: **сервер на ноутбуке
преподавателя**, **Android-телефон преподавателя эмулирует NFC-метку**,
**iPhone студента её читает**. Интернет не нужен — только Wi-Fi (или USB-модем)
между ноутбуком и телефонами. Никакой публикации в интернете.

| Компонент | Технологии | Папка |
|---|---|---|
| Локальный сервер | Python 3.11+, FastAPI, SQLite | [`server/`](server/) |
| Телефон преподавателя | Kotlin, HCE (HostApduService), Room, Retrofit | [`android/`](android/) |
| Телефон студента | Swift + SwiftUI, CoreNFC (NDEF), Core Data | [`ios/`](ios/) |
| Документация | схемы БД, установка, подпись, тесты | [`docs/`](docs/) |

Документы: [схема БД](docs/DB_SCHEMA.md) · [установка и подпись iOS/Android](docs/INSTALL_AND_SIGNING.md) · [тестовый сценарий](docs/TEST_SCENARIO.md)

## Как это работает

```
        Wi-Fi (роутер или точка доступа ноутбука) — интернет не нужен
   ┌────────────────┐        POST /api/session, /api/sync        ┌──────────────┐
   │  Ноутбук       │ ←──────────────────────────────────────── │  Android     │
   │  преподавателя │                                            │  преподава-  │
   │  FastAPI +     │        POST /api/attendance                │  теля (HCE)  │
   │  SQLite        │ ←──────────────────────────────────────── │              │
   └────────────────┘                                          └──────────────┘
            ▲                                                          ▲
            │ GET /api/attendance/{session_id}                         │ NFC-метка
            │                                                       (NDEF)
   ┌────────────────┐  iPhone читает метку → сохраняет в Core Data →  отправляет на сервер
   │  iPhone         │
   │  студента       │
   └────────────────┘
```

1. **Преподаватель** запускает сервер: `uvicorn main:app --host 0.0.0.0 --port 8000`.
2. В Android-приложении создаёт пару: предмет, группа, свой идентификатор, длительность.
3. Android-приложение включает HCE: телефон становится **NDEF Type 4 Tag** с сообщением

   ```json
   {"session_id":"0f8c…-UUID","subject":"Информатика",
    "teacher_id":"IVANOV_II","timestamp":"2026-10-04T10:15:00+03:00"}
   ```

4. **Студент** открывает iPhone-приложение и нажимает «Отметиться».
5. CoreNFC (`NFCNDEFReaderSession`) читает NDEF-сообщение с телефона преподавателя.
6. Отметка сохраняется локально в **Core Data** — сразу, даже если сети нет.
7. Приложение отправляет `POST /api/attendance` на сервер; при отсутствии сети
   отметка ждёт в очереди и уходит автоматически (повторы 5 с → 15 с → 45 с → 2 мин).
8. Android-приложение отправляет на сервер свои пары и «касания» (`POST /api/sync`).
9. Сервер сверяет отметку с касанием и отдаёт список присутствующих:
   `GET /api/attendance/{session_id}`.

### Резервный путь: QR-код (важно для iPhone)

Чтение NFC на iOS требует capability **NFC Tag Reading**, а её Apple выдаёт
**только по платному аккаунту разработчика ($99/год)** — с бесплатной подписью
CoreNFC не работает ([источник](https://www.freecodecamp.org/news/the-ios-nfc-handbook-how-to-read-write-and-lock-nfc-tags-with-react-native)).
Поэтому в системе есть второй, полностью рабочий путь:

* преподаватель открывает в Android-приложении **«Показать QR-код для iPhone»** —
  на экране крупный QR с тем же JSON, обновляется каждые 5 секунд;
* студент в iOS-приложении нажимает **«Отметиться по QR-коду»** и наводит камеру
  (камера особых разрешений Apple не требует — бесплатная подпись подходит);
* каждое обновление QR регистрируется как «касание» на стороне преподавателя,
  поэтому отметки по QR сервер считает подтверждёнными.

Оба пути опираются на одну и ту же логику: сервер, база и античит — общие.

## Быстрый старт

### 1. Сервер (ноутбук преподавателя)

```bash
cd server
python -m venv .venv
# Windows:  .venv\Scripts\activate
# macOS/Linux:  source .venv/bin/activate
pip install -r requirements.txt

uvicorn main:app --host 0.0.0.0 --port 8000
# или просто:  python main.py     (покажет адреса, по которым сервер видно в сети)
```

Что должно появиться:

```
==============================================================
  КубГАУ · Сервер посещаемости запущен
  База: …/server/attendance.db
  Локально:  http://127.0.0.1:8000/docs
  В сети:    http://192.168.1.10:8000   ← этот адрес вводите на телефонах
==============================================================
```

Проверка: откройте `http://<IP ноутбука>:8000/` с телефона — увидите страницу
«Сервер посещаемости работает». Разрешите Python доступ в локальной сети,
если Windows спросит (или разрешите порт 8000 в брандмауэре).

Тесты сервера: `cd server && pytest -v` (16 проверок: приём, дубли, античит, синхронизация).

### 2. Android-приложение преподавателя

* CI собирает APK автоматически: раздел **Releases → `nfc-v1.0.0`** →
  `NFC-Attendance-Teacher.apk`.
* Установка по кабелю: `adb install -r NFC-Attendance-Teacher.apk`
  (или просто скинуть файл на телефон и открыть).
* Локальная сборка: откройте папку `android/` в Android Studio (JDK 17) или
  `cd android && gradle assembleRelease`.

В приложении: укажите адрес сервера (например `192.168.1.10`), нажмите
«Проверить связь», заполните предмет/группу/свой id, «Создать пару»,
затем **«Начать эмуляцию метки»** — телефон готов принимать касания.

### 3. iOS-приложение студента

* CI собирает **неподписанный** `.ipa`: раздел **Releases → `nfc-v1.0.0`** →
  `NFC-Attendance-Student-unsigned.ipa`.
* Подпишите его своим Apple ID через **Sideloadly** (бесплатно, 7 дней) и
  установите по кабелю — пошагово: [docs/INSTALL_AND_SIGNING.md](docs/INSTALL_AND_SIGNING.md).
* Если есть платный аккаунт разработчика — просто откройте `ios/` в Xcode
  (`xcodegen generate` нужен один раз) и запустите на своём iPhone.

В приложении: вкладка «Настройки» → адрес сервера и логин (со вкладки «Студенты»
на ПК) → вкладка «Отметиться» → **«Отметиться»** (NFC) или **«Отметиться по QR-коду»**.

## API сервера

| Метод | Путь | Кто вызывает | Назначение |
|---|---|---|---|
| `GET` | `/api/health` | оба приложения | проверка связи |
| `POST` | `/api/session` | преподаватель | создать пару (UUID) |
| `GET` | `/api/sessions` | преподаватель | список пар |
| `GET` | `/api/session/{id}` | оба | данные пары, счётчик присутствующих |
| `POST` | `/api/session/{id}/close` | преподаватель | закрыть пару |
| `POST` | `/api/attendance` | студент | прислать отметку |
| `GET` | `/api/attendance/{id}` | оба | присутствующие + отклонённые попытки |
| `GET` | `/api/attendance/{id}/export.csv` | преподаватель | выгрузка в Excel |
| `POST` | `/api/tap` | преподаватель | одно касание терминала |
| `POST` | `/api/sync` | преподаватель | пары + касания одним запросом (идемпотентно) |
| `GET` | `/api/sync/state` | преподаватель | что сервер уже знает |
| `POST` | `/api/students/register` | любой | завести студента (логин → ФИО, группа) |
| `GET` | `/api/students` | любой | список студентов |

Ответы на отметку:

| Код | `result` / `reason` | Значение |
|---|---|---|
| 200 | `accepted` | принята и подтверждена касанием терминала |
| 200 | `accepted_unverified` | принята, касания рядом по времени не было |
| 200 | `duplicate` | уже отмечался в эту пару (вторая запись не создаётся) |
| 404 | `unknown_session` | пары нет на сервере |
| 409 | `session_closed` / `session_expired` | пара закрыта или истекла |
| 409 | `subject_mismatch` / `teacher_mismatch` | данные метки не совпали с парой |
| 409 | `device_mismatch` | телефон привязан к другому студенту |
| 409 | `no_device_id` | приложение не передало `device_id` |

Документация Swagger — `http://<IP>:8000/docs`.

## Protokol NDEF-метки

| Что | Значение |
|---|---|
| Формат метки | NDEF Type 4 Tag (ISO 7816-4) |
| AID | `D2760000850101` (NFC Forum NDEF) и `F0391101020304` (собственный) |
| Файлы | `E103` — CC, `E104` — NDEF (макс. 1024 байта) |
| Запись | MIME `application/vnd.kubgau.attendance+json`, payload — JSON выше |
| Обновление | timestamp пересобирается на каждое касание |

## Защита от обмана

* **`session_id` — случайный UUID**, свой на каждую пару: заготовленная метка
  не подойдёт к другой паре.
* **Сверка метки с парой на сервере**: предмет и преподаватель из метки должны
  совпадать с парой, иначе 409.
* **Повторная отметка** в ту же пару блокируется (уникальность `session_id + student_id`).
* **`device_id` генерируется один раз** на iPhone (хранится в Keychain, переживает
  переустановку). Отметка с чужого телефона — `device_mismatch`.
* **Сверка с касанием терминала**: отметка без касания рядом по времени
  принимается, но помечается `verified = 0` — преподаватель видит «без касания».
* **Живой QR**: код обновляется каждые 5 секунд, скриншот бесполезен.
* Все отклонённые попытки пишутся в `rejected_marks` — видно, кто и по какой
  причине пытался отметиться.

## Ограничения

* Только локальная сеть: телефон и ноутбук должны быть в одной Wi-Fi-сети
  (либо через USB-модем, если роутера нет).
* iPhone **читает** NFC, но не эмулирует: HCE на iOS недоступна — поэтому в
  паре всегда есть Android-телефон преподавателя.
* CoreNFC требует платный Apple Developer Account; QR-путь от него не зависит.
* Бесплатная подпись iOS живёт 7 дней — потом приложение нужно подписать заново
  (данные в Core Data при этом сохраняются).
